## Four new features added to DESIGN_LOCAL_v4.md

### 1. Recurrent Dashboard (§11) — *spec added, component already in tree*

Fully specified UI flow for the `recurrent-dashboard/` component that already existed in the component tree. No new route or component needed.

| Aspect | Detail |
|---|---|
| Route | `recurrent-transactions/dashboard` (`RECURRENT_DASHBOARD` — already in catalog) |
| Component | `RecurrentDashboardComponent` (already in tree) |
| Status logic | DONE / PENDING / NOT_YET_DUE per §5.6 of BUSINESS_LOGIC.md |
| Sort order | PENDING → NOT_YET_DUE → DONE |
| Actions | "Mark as done" (no transaction link) and "Link transaction" (MatDialog) — both create `RecurrentTransactionMatch` with `strMatchMode: 'MANUAL'` |
| Writes | `pfmg_recurrent_matches` only |

### 2. Transaction Explorer (§12) — *new top-level feature*

| Aspect | Detail |
|---|---|
| Route | `explorer` (`EXPLORER` — new in catalog) |
| Component | `TransactionExplorerComponent` (new `explorer/` feature) |
| Filters | Category `<mat-select>` → Subcategory `<mat-select>` (reactive); optional account filter |
| Results | All ACTIVE + PENDING transactions for selected `subcategoryId`, sorted by date DESC |
| Use case | "When was my last haircut?" — most recent matching transaction appears first |
| No writes | Read-only feature; no localStorage writes |

### 3. Monthly Income/Expense Dashboard (§13) — *new feature*

| Aspect | Detail |
|---|---|
| Route | `dashboard/monthly` (`DASHBOARD_MONTHLY` — new in catalog) |
| Component | `MonthlyDashboardComponent` (new `dashboard/` feature) |
| Month nav | Prev/Next buttons; defaults to current month |
| Income | Sum of `decAmountPen > 0` across all accounts |
| Expenses | Sum of `decAmountPen < 0` across all accounts (display as abs) |
| Breakdown | Grouped by subcategory, sorted by abs(total) DESC; uncategorized shown last |
| Algorithm | `DashboardCalculatorService.computeMonthly()` (new pure service §7.6) |
| No writes | Read-only feature |

### 4. Per-Card Cycle Expense Dashboard (§14) — *new feature*

| Aspect | Detail |
|---|---|
| Route | `dashboard/cycle` (`DASHBOARD_CYCLE` — new in catalog) |
| Component | `CycleDashboardComponent` (under same `dashboard/` feature) |
| Scope | Credit cards only (debit accounts excluded) |
| Per-card widget | Cycle window, total expenses, payments, current balance, top 3 subcategories |
| Cycle window | Reuses `ConciliationCalculatorService.buildCycleWindow()` per card's `intClosingDay` |
| Algorithm | `DashboardCalculatorService.computeCycleSummary()` (new pure service §7.6) |
| No writes | Read-only feature |

## New service: DashboardCalculatorService (§7.6)

Pure, stateless service in `src/app/core/services/dashboard-calculator.service.ts`.

| Method | Purpose |
|---|---|
| `computeMonthly(month, transactions, subcategories, categories)` | Monthly income/expense totals and subcategory breakdown |
| `computeCycleSummary(card, todayDate, transactions, subcategories, categories)` | Per-card cycle summary; calls `ConciliationCalculatorService.buildCycleWindow()` internally |

Has one injected dependency: `ConciliationCalculatorService` (for cycle window). All other inputs are plain data.
